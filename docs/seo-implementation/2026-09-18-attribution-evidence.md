# Attribution evidence for the CRE SEO and AI search audit

Reviewed September 18, 2026. This appendix records repository evidence, changes made during the audit, and measurement gaps. It does not establish current traffic, rankings, AI citations, live account configuration, or successful delivery of an actual lead.

## Verified implementation

- **Coverage:** 358 of 384 public HTML files load `js/site-config.js` and `js/funnel.js`, including the CRE pages reviewed. Four use the separate Family runtime and 20 use navigation-only blog JavaScript. Privacy exclusions and private planning tools must remain excluded.
- **Configured analytics:** `js/site-config.js:18` contains public GA4 and Meta identifiers. `js/funnel.js:26` initializes the tags. A configured identifier is not proof that the correct account receives data or that its reports are configured correctly.
- **Accepted inquiry measurement:** `js/funnel.js` calls `generate_lead` inside `done()` only after successful submission delivery. Its parameters are `form_id`, `product`, and `language`. Attempts, errors, legacy product-specific success events, and phone-link clicks are separate events. `tests/growth-measurement.test.mjs` verifies accepted versus failed delivery, repeated clicks, honeypots, attribution preservation, and exclusion of contact details from analytics parameters.
- **Saved source details:** `js/funnel.js:81` captures six UTM fields plus `gclid` and `fbclid` in session storage. These are included in `extra.utm`; the current submission path and bounded query string also appear in `about`. Later tagged arrivals replace the session attribution object. `about` has a 2,000-character cap, whereas structured UTMs remain separate.
- **CRM forwarding:** `netlify/functions/submission-created.js:24` forwards the saved Netlify lead fields, preserves structured extras and adds `netlify_submission_id`. It checks the CRM response and retries with a stable submission identity. Activation depends on server environment configuration, which this audit did not inspect. Dedicated Residential, HELOC and Family page identities retain the existing Residential routing rule.
- **ChatGPT Ads:** `js/chatgpt-pixel.js` measures a page view and accepted `lead_created` conversion with an opaque event ID. It suppresses sensitive Family pages, confirmation pages and Global Privacy Control sessions. `docs/chatgpt-pixel.md` documents coverage and limitations. The advertising pixel is not an organic ChatGPT citation report.
- **Existing privacy boundaries:** `js/family-config.js:16` leaves Family GA4 blank and disables analytics on sensitive pages. `js/family-lp.js` applies the separate tracking policy. These exclusions were not expanded or removed.

## Defects corrected during this audit

1. **Selected financing type could differ from the saved product.** `commercial.html`, `sba.html` and their Spanish equivalents use `select[name="product"]`. The shared runtime previously synchronized only `product_choice`, leaving the top-level CRM product and GA4 product at the page default. The choice survived in extra details but was misclassified at the top level. `js/funnel.js` now supports both selector names, accepts recognized product lanes, and refreshes the value at submission. Forms with a fixed product and no selector retain that product. Tests cover all four actual page templates, existing Residential selection, and unsupported values.
2. **Calculator engagement counted default examples.** `commercial-loan-calculator.html` and `sba-loan-calculator.html` called their calculation functions on page load, which also emitted `calc_used`. Both still render examples immediately, but now measure use only after an input interaction producing a valid result. SBA program/checkbox changes also qualify. `tests/calculator-engagement.test.mjs` exercises actual inline scripts, invalid inputs, initial rendering and duplicate event suppression.

The shared runtime version is now `funnel.js?v=12` across all 358 public references and the three generator templates that specify it. Validation: `node scripts/check-site.mjs` passed with **77 tests**, all page lints and the SEO/content gates. No production lead was submitted for testing. Commit and deployment are handled in the main audit release.

## Account checks and interpretation boundaries

- Verify that `generate_lead` is the one primary inquiry key event. Do not sum it with `lead`, `quote_request`, `deal_review_request`, `form_submit_succeeded`, automatic form events or confirmation-page visits for the same submission.
- A `phone_click` is not proof of a connected call or qualified borrower. A captured inquiry is not proof of CRM acceptance, financing eligibility or funding.
- Check the owner's GA4, Search Console and Bing Webmaster reports before asserting volumes, trends or citation share. This repository audit did not access those account metrics, server environment values or private lead records.
- Distinguish identifiable AI referrals from paid campaigns and ordinary organic search. Missing referrers remain unknown; do not infer that every direct visit is an AI visit. An optional self-reported discovery source can supplement, but cannot replace, observed evidence.
- Track qualified CRE opportunities and mature funded outcomes alongside visibility. Advertising blockers, browser privacy and deliberate tracking exclusions can undercount browser analytics. Netlify and CRM records provide separate storage evidence.
- Do not send financial balances, credit scores, free-text scenarios or contact fields to general analytics to improve attribution. No attribution model, offline import or new tracking integration was implemented here.
